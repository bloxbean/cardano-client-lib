Test locally with Yaci DevKit

You can run every tutorial on this site in one of two places: a devnet on your own machine, or a public test network. Both use the same code, and only the backend line changes.

Yaci DevKit (local)Preview or Preprod (public)
SetupInstall and start it onceNothing to install. Blockfrost needs a free project id; Koios doesn’t
Test adaFunded accounts, plus a top-up commandA faucet
Block time1 second by defaultAbout 20 seconds on average
Epoch length600 slots by default, and you can change it1 day on Preview, 5 days on Preprod
Who sees itOnly youEveryone, permanently
Start overReset whenever you likeNot possible

Use DevKit while you’re developing, because the feedback is fast and mistakes cost nothing. Before you release, run once on Preview: a public network has real delays that a devnet hides.

Use the Yaci CLI prompt

Section titled “Use the Yaci CLI prompt”

Both setups leave you at an interactive prompt, devnet:default>, where you can manage the devnet. Keep that terminal open while you work.

The command reference lists the rest. For a test pipeline that doesn’t need a prompt, leave out --interactive and fund accounts over HTTP.

See your transactions in Yaci Viewer

Section titled “See your transactions in Yaci Viewer”

Yaci Viewer is a block explorer for your devnet, in your browser. Use it to look up the blocks, transactions and addresses that your code creates.

Move to a public network

Section titled “Move to a public network”

Change the backend, and use an account you funded from the faucet in place of the devnet mnemonic. The rest of your code stays the same:

Expect two differences:

  • Slower confirmation. Allow minutes rather than seconds, for example with completeAndWait(Duration.ofMinutes(5)). If it times out, the status is TIMEOUT and the transaction may still land.
  • Delays in the backend’s view. A confirmed transaction’s outputs can take a little while to appear in UTxO queries, so a step that spends them straight away may not find them. Retry that query instead of assuming they’re there.

Going further

Section titled “Going further”
  • Staking and governance. The staking lifecycle spans several epochs, which takes minutes on a devnet instead of days. The --epoch-length option of create-node makes them shorter.
  • Starting over. reset at the Yaci CLI prompt deletes the devnet’s data and restarts it.
  • Rollbacks. DevKit can also simulate rollbacks, which is useful for testing TxFlow.
  • Other commands. See the command reference and the services DevKit can run.
